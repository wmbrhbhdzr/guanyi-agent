> 版本：V1　｜　日期：2026-09-13　｜　作者：Wang Yuchen

## 1. 项目概述

**一句话定位**：以屏幕像素为唯一输入，用视觉语言模型在离散决策游戏中提供带依据的决策建议与逐回合复盘。

**核心价值**：把"凭手感打"变成"有依据地改进"。

**与现有方案的差异**

1. **像素优先**：决策层输入只有屏幕截图，不读取任何游戏内部数据（内存、存档、日志、Mod 接口）。
2. **真值隔离**：游戏内部状态仅用于离线评测与动作合法性校验，**不进入模型上下文**。
3. **可复现评测**：固定种子局面集 + 三类基线（随机／规则脚本／人类），使"是否变好"可量化。
4. **记忆机制可验证**：把"学习"实现为可检查的记忆级机制，并做有无对比。

## 2. 用户

### 2.1 主用户

单机策略／卡牌类游戏玩家（本科在读，重度玩家为主）。

| 维度 | 内容 |
| --- | --- |
| 目标 | 提升水平；理解"为什么这样打更好" |
| 能力 | 熟悉游戏机制，会装软件，不具备编程能力 |
| 环境 | Windows 笔记本电脑，游戏窗口化运行，单人使用 |
| 约束 | 不修改游戏本体、不使用外挂；**不接受整屏被截取**；对等待敏感 |
| 痛点 | 缺少客观复盘依据；能感到失误却无法定位；重复对局耗时 |

**调研依据**（N=10，详见 `docs/问卷结果.md`）：Q4 中 80.0% 仅“偶尔回想”、20.0% 不复盘，且无人采用系统化复盘；Q5 60.0% 有“打错却不自知”的困扰；Q7 40.0% 认为现有方式最大不足是“讲的是典型局面、对不上自己的具体情况”、30.0% 为“不知道自己的判断到底对不对”；Q12 50.0% 要求只截游戏窗口、另有 20.0% 要求完全本地处理。

### 2.2 次用户

学习或开发 VLM 智能体的学生与开发者：需要可复现的"读屏—决策—记录—评测"参考实现与评测基线。

### 2.3 明确不做

- **在线游戏的日常任务／刷素材自动化**（MMORPG 刷素材、开放世界日常任务等）。**该方向并非不可为，而是不适合本项目**——该领域已有大量成熟开源实现（合计约 4.5 万星标且持续活跃），说明"读屏 → 识别 → 模拟输入"路线已被验证可行；但对本项目不合适，理由：① 违反目标游戏用户协议，账号风险由使用者承担（部分游戏 EULA 明确将"自动完成任务"列为未经许可的第三方软件）；② 反作弊与版本对抗需多年持续维护，非一人一学期可及；③ 该领域技术路线为针对特定游戏的计算机视觉适配，与本项目"通用 VLM 决策 + 可复现评测"的命题不匹配；④ 与本项目用户调研结论不一致（用户要建议而非代打，见第 3 节）；⑤ 同类项目多为 AGPL／GPL 强传染性许可，会约束本项目的开源许可选择。详见实验2 报告 3.3.2。
- 地图选路／商店／事件／遗物取舍、战后选牌、多角色与高难度、完整一局通关。
- 实时动作类游戏、模型自训练与权重级微调、跨游戏泛化验证。

## 3. 核心用户流程（本学期唯一重点）

```
玩家在一场战斗中启动观弈
  → 截取游戏窗口区域画面
  → 按所选提示强度档位工作（默认「仅复盘」，游玩时不介入）
  → 记录：局面 / 建议 / 玩家实际操作 / 结果
  → 战斗结束输出逐回合复盘报告（含关键决策点与依据）
  → 自动化执行仅用于「玩家显式开启的练习模式」与「批量评测」
```

> **依据**：问卷 Q9 中"自动替我完成重复的战斗"得票 2/10（20.0%），而"每回合给出建议和理由"得票 50.0%，故自动执行被定位为**可选能力**而非核心能力。
>
> **定位（教练而非替身）**：策略类游戏的核心乐趣是决策本身，替玩家决策等于消灭游戏。观弈定位为**教练**——像棋手用 AI 复盘一样帮助玩家理解，**决策权始终在玩家**。围棋界的实践已给出区分：**“AI 代打”被禁止，“AI 复盘”是公认的正当训练**。故**不做代打**，并新增“提示强度三档可调（默认仅复盘）”。
>
> **自动化的三层定位**：① 评测执行器（必需，服务于可复现评测）；② 自动化接口（保留，服务于扩展与后续游戏适配）；③ 玩家自动执行（可选、默认关闭）。三者为同一 `Executor` 抽象的三种实现，其中 DryRun 实现即“仅复盘”模式——**感知必须通用，执行可以专用**。

## 4. 功能需求

| 编号 | 功能 | 优先级 | 验收方法 |
| --- | --- | --- | --- |
| FR-01 | 采集游戏窗口区域画面并校验有效性 | 高 | 截图非黑屏、非空，内容仅含游戏窗口 |
| FR-02 | 由截图生成结构化建议（动作 + 依据） | 高 | 输出可解析为合法动作 JSON |
| FR-03 | 动作合法性校验（规则护栏） | 高 | 非法建议被拦截并记录 |
| FR-04 | 逐决策点记录（JSONL，可回放） | 高 | 日志含局面／建议／实际操作／结果四项 |
| FR-05 | 生成逐回合复盘报告 | 高 | 报告含每回合四项信息，标出关键决策点 |
| FR-06 | 失败恢复（动作无效、服务异常、返回为空） | 高 | 不出现无限重试；有明确中文提示 |
| FR-07 | 固定局面集批量评测与指标输出 | 中 | 输出胜率／平均损耗与方差 |
| FR-08 | 结构化记忆机制 | 中 | 有无记忆的对比实验产出数据 |
| FR-09A | 自动执行器（可插拔）：DryRun／键鼠注入／预留游戏专用通道 | **高**（评测必需） | 三种执行器可互换；决策层不依赖具体实现；DryRun 下无真实输入注入 |
| FR-09B | 自动化接口：给定局面 → 动作序列／执行本回合 | 中 | 可被独立脚本调用并产出结构化结果 |
| FR-09C | 玩家自动执行入口（练习模式，默认关闭） | 低 | 画面发生预期变化；玩家可随时中断 |
| FR-10 | 提示强度三档可调（仅复盘／卡关时建议／逐决策点建议），**默认仅复盘** | **高** | 切换后行为符合档位；默认档不介入游玩 |

## 5. 非功能需求

| 类别 | 需求 |
| --- | --- |
| **性能** | 单次决策端到端时延目标 P50 ≤ 3 s、**P95 ≤ 5 s**（依据 Q11：80.0% 用户容忍上限在 5 秒内）；支持无人值守批量运行；单局成本可核算并受上限约束 |
| **性能** | 阈值说明：实测当前为 1942–8321 ms，**尚未达标**；缓解措施见第 7 节 |
| **可靠性** | 动作注入失败必须被检出并停止重试（上限 2 次）；模型返回为空／非法必须拦截；固定种子与固定模型版本下决策序列可复现 |
| **安全** | **仅截取游戏窗口区域，不采集整屏**（Q12：50.0% 明确要求）；API 密钥仅通过环境变量读取；截图、日志与运行记录不入版本库 |
| **可用性** | 启动后无需命令行操作；失败信息为人类可读中文，并说明可采取的动作 |
| **可扩展性** | 动作执行器必须可插拔，决策层不得依赖任何具体执行实现；“仅复盘”模式由 DryRun 执行器提供 |

## 6. 验收条件（核心流程，Given/When/Then）

| # | 类型 | Given | When | Then |
| --- | --- | --- | --- | --- |
| A1 | 正常 | 战斗画面、手牌清晰可辨 | 完成一次决策 | 输出可解析的合法动作、画面正确响应，日志记录四项 |
| A2 | 正常 | 固定种子局面集 | 批量运行 20 局 | 全部完成无崩溃，产出胜率与平均损耗及方差 |
| A3 | 信息不足 | 画面被遮挡或手牌不可辨 | 模型无法确定局面 | 输出"无法识别"并暂停等待人工处理，记录 `low_confidence`，**不得猜测** |
| A4 | 失败 | 已执行动作但画面无变化 | 重试 2 次仍无效 | 记录 `injection_failure`、停止自动执行并提示，**不得继续重试** |
| A5 | 需人工确认 | 模型输出与规则校验冲突 | 冲突发生 | 拦截动作、以规则为准、记录 `guardrail_trigger`、提示玩家确认 |

## 7. AI 能力与风险

### 7.1 模型输入／输出／边界

| 项 | 内容 |
| --- | --- |
| 输入 | 游戏窗口区域截图 + 与游戏无关的通用动作 schema 说明 |
| 期望输出 | 结构化结果：动作类型 + 目标 + 一句依据；无法确定时输出"无法识别" |
| 允许错误 | 单决策点的次优建议、依据表述不精确 |
| **不可接受** | 非法动作、空返回、崩溃、无限重试、把不确定的局面当成确定的 |
| 人工确认点 | ① 首次使用／更换游戏时确认截图区域；② 动作连续 2 次未生效时；③ 模型输出与规则冲突时；④ 切入自动模式时 |

### 7.2 规则与 AI 的边界

**动作合法性校验、失败重试、记录与统计必须用规则实现，不交给模型。** 规则护栏是 AI 的必要配套，而非替代。

### 7.3 已实测的关键数据

| 项 | 实测值 | 影响 |
| --- | --- | --- |
| 单次决策时延 | 1942 – 8321 ms | **超出多数用户容忍范围**（Q11：80.0% ≤ 5 s）；故游戏类型收敛为离散决策 |
| 单次决策费用 | 0.0014 – 0.0067 元 | 1000 局约 37–219 元，可承受 |
| 输出 token 占比 | 总费用的 **84%** | 压缩输出是降本与降时延的共同手段 |
| 读数准确率 | 清晰大字号 100% 正确；密集小字界面出现误读 | **不能假设"模型读屏必然正确"**，必须设计校验；"看不清就明说"约束实测有效 |

### 7.4 非 AI 降级方案

降级为**规则脚本决策**：保留截图、执行、记录、评测、复盘报告，仅把决策层换成固定启发式规则。

- 代价：只能处理规则可覆盖的固定局面，失去通用性。
- 价值：系统仍是完整可运行的软件；且该规则脚本本身即是评测所需的**规则基线**——降级方案是评测体系的组成部分，而非失败退出。

## 8. MVP 范围

**纳入**：画面采集（限游戏窗口）、局面识别与决策、规则护栏、决策点记录、复盘报告、评测与基线、结构化记忆、最小界面；动作执行为低优先级可选项。

**不纳入**：见 2.3。

**阶段与目标**

| 阶段 | 周次 | 目标 |
| --- | --- | --- |
| P0 探针 | 2–3 | 截图（限窗口）／注入／读数三个探针出结论 |
| P1 闭环 | 4–8 | 能完成一场战斗并产出记录；实测时延分布 |
| P2 记忆与稳健 | 9–12 | 护栏与失败恢复；记忆有无对比实验 |
| P3 评测与收敛 | 13–17 | 固定局面集评测报告 + 完整文档 |
