# 视觉识别运行说明

当前主链路为“连接游戏窗口 → 采集画面 → 视觉模型提取 → 程序校验 → 展示与保存”。导入图片保留为固定样例复测入口。
当前状态来自主动选择的图片，不读取历史对局、存档或游戏进程。通用模式不加载游戏资料；
“杀戮尖塔2”模式加载少量公开外形参考与界面显示约定，身份匹配和规则补充会注明来源。
窗口单次与连续采集已接入；当前不会自动操作游戏。

## 连接游戏窗口

1. 启动游戏并保持非最小化，打开观弈“游戏画面识别”页。
2. 点击“自动连接游戏”。只有一个匹配游戏窗口时自动选中；多个候选或未匹配时，点“刷新窗口”后从列表手动选择。
3. 点击“采集预览”，在本地确认画面属于目标游戏。这一步不会请求模型。
4. 点击“采集并识别”完成一次读取，或设置1—300秒后点“开始连续识别”。
5. “暂停 / 停止”取消后续定时采集；已发出的模型请求不能保证在服务端取消，但晚到结果不会继续更新当前任务。

连续识别默认间隔5秒，计时从前一次任务结束后开始，不是无论接口是否完成都每5秒发一次请求。
画面像素完全相同时跳过调用；动画或鼠标悬停引起像素变化仍可能触发识别。
窗口关闭、最小化、捕获黑屏或识别失败会停止连续任务，处理原因后可重新开始。
STS2窗口匹配后自动选择对应识别适配；PVZ目前只包含窗口发现规则，其专用局面解析未实现。

Windows实现通过PrintWindow读取所选窗口客户区，不采整个桌面、不读游戏内存，不改变游戏焦点或发出按键。
某些全屏/硬件加速游戏可能黑屏或停帧，可先尝试窗口化或无边框模式；当前未接伪最小化。
后台被遮挡能否获得新帧要在实际游戏中核验，不能将接口成功等同于画面一定在更新。
采集线程使用Per-Monitor DPI Aware V2，避免系统缩放造成尺寸虚拟化。

```powershell
# 列出可见窗口与进程信息，不调用模型
.\.venv\Scripts\python.exe -m guanyi.cli windows --list

# 只有一个已支持窗口时自动选择，只采集预览
.\.venv\Scripts\python.exe -m guanyi.cli windows

# 指定列表中的句柄（下面0x1234仅示意，需替换为真实值）
.\.venv\Scripts\python.exe -m guanyi.cli windows --hwnd 0x1234 --recognize
```

输入图与采集元数据保存在`data/window_capture/capture-<编号>/`，记录窗口/PID、方法、尺寸、哈希和结果。
进程元信息用于关联窗口，当前数值只取自像素；不会把PID、文件路径或窗口列表发送给视觉模型。
采集超时仅停止等待；同一后台采集未结束时拒绝新采集，避免线程堆积。

## 导入图片进行复测

在项目目录启动：

```powershell
.\.venv\Scripts\python.exe -m guanyi.ui
```

1. 打开“游戏画面识别”页，点击“导入测试图片”。建议先在游戏内截图，再裁成只包含游戏区域的图片。
2. 预览只在本地进行，不会请求模型。确认选图正确后点击“识别导入图片”，将图片上传至 `.env` 配置的模型服务。
   默认“自动（按标题）”会先用图片中可见的标题确认游戏；识别为Slay the Spire 2后启用对应适配。
   可手动选“杀戮尖塔2”跳过标题检查，或选“通用识别”明确禁用专用规则。结果状态栏会显示实际采用的适配。
3. 在“局面摘要”核对血量、能量、格挡、回合、手牌与敌人意图；“完整结果”显示结构化字段。
4. 不清楚的值保持“未识别”，不会默认填入0、80或3。可以换用更清晰的截图重新识别。
5. 本页不会自动把结果填到“核心任务页”，也不会把识别结果当成已校验的合法动作。

识别在后台线程执行，等待期间可以切换页面；重复点击不会并发发起多次识别。
关闭窗口不保证服务端请求取消，已发出的请求仍可能产生用量。

## 命令行使用

```powershell
# 真实图片：按需替换路径，会请求模型并保存结果
.\.venv\Scripts\python.exe -m guanyi.cli vision --image "C:\截图\战斗.png"

# 杀戮尖塔2：启用显示规则、敌人与增减益图标参考
.\.venv\Scripts\python.exe -m guanyi.cli vision --image "C:\截图\战斗.png" --game sts2

# 可设置最长等待，或仅输出而不保存
.\.venv\Scripts\python.exe -m guanyi.cli vision --image "C:\截图\战斗.png" --timeout 45 --no-save

# 可复核的合成画面：只生成图片，不请求模型
.\.venv\Scripts\python.exe scripts\vision_demo.py

# 同一张合成画面调用真实模型，并在模型外核对11项结果
.\.venv\Scripts\python.exe scripts\vision_demo.py --online
```

沿用 `.env` 中的 `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL` 和现有 `deepseek-flash` 调用方式。
只使用已列入依赖的 Pillow 和标准库，不需额外安装模型、OCR框架或GPU推理环境。

## 识别范围与字段

| 字段 | 内容 |
| --- | --- |
| `scene` | combat / map / reward / menu / unknown |
| `turn` | 明确可见的回合数，正整数或null |
| `player` | hp、max_hp、energy、max_energy、block，未知为null |
| `hand` | 卡牌数组；每张记录name、cost、upgraded；费用可为整数、X或null |
| `enemies` | 多敌人数组，含名称、血量、格挡、意图原文、单次伤害与攻击次数 |
| `uncertainties` | 模型指出的模糊、遮挡或缺失信息 |
| `player.statuses` / `enemies[].statuses` | 血条下方增减益：name和amount；数值可为负数或null，未知名称保留图标条目 |
| `tooltips` | 悬停窗口可见标题、说明文字、所属player/enemy/unknown和从0开始的敌人序号；关联不明保留null |

`hand: null`表示区域不清楚，`hand: []`表示画面明确显示没有手牌；敌人同理。
名称尽量保留画面原文，不根据插图补牌名；多段攻击的伤害与次数分别记录，不推断未显示的次数。
现已加入血条下增减益图标与可见数值的提取；遗物、药水、地图路线仍未实现。

输入限制：PNG/JPEG/WebP/BMP静态图片，最多20 MB、4000万像素，至少64×64；
最长边缩放至1920，纠正EXIF朝向并剥离图片元数据。纯黑/纯白空画面在本地拒绝。
程序校验字段、类型、范围和血量关系，拒绝残缺JSON、重复字段、未声明字段与长度截断的模型输出。
这些检查只能验证结构和部分一致性，不能证明模型读数必然准确。

## 结果与运行记录

```text
data/vision/vision-<唯一编号>/input.png    实际提交的标准化图片
data/vision/vision-<唯一编号>/result.json  结果、原始回答、错误、用量、耗时及本地估算费用
runs/vision_demo/frame.png               合成测试图
runs/vision_demo/check.json              合成图11项核对结果
```

记录还包括输入图尺寸、原始文件及实际提交图片的SHA-256、提示词版本 `vision-v1`。
不记录密钥、请求头或图片Base64；`data/`和`runs/`已忽略，不会随普通Git提交上传。
费用沿用项目现有单价表估算，应以服务账单为准。

2026-11-10起使用提示词 `vision-v4`，提取调用显式关闭深度思考，输出预算4096，避免推理占满预算而答案为空。
失败时局面摘要会显示具体错误、建议处理方式、尝试数及结束原因；“完整结果”显示错误详情、用量和原始答案。
`output_limit`表示输出预算耗尽，`http_401`表示鉴权失败，`http_402`通常为余额问题，
`http_429`表示限流，`network_error`为连接故障，`invalid_observation`为返回结构不符合要求，不能混为“没结果”。

杀戮尖塔2模式：完整可见的格挡区域没有盾牌即按该游戏显示约定读0；完整攻击意图无乘号为1次。
被遮挡/裁掉时继续保留null，不在所有游戏中全局补0或1。非攻击意图不显示“次数未识别”。
笨拙精确识别后标记为诅咒、不可打出、虚无，费用null；rules_source和normalizations记录规则来源。
敌人名称可来自参考图外形匹配，需核对；增减益数字不一定是层数或回合数，例如难以杀灭9是伤害上限。
没有显示数字不默认1；图标名称不明时保留可见数值。当前仅4种敌人与8种状态参考，暂不保证完整覆盖或所有图标匹配正确。

悬停窗口现在优先作为像素文字读取，“局面摘要”末尾显示独立的悬停详情；
只有明确关联到该对象的同名状态才补充`source: tooltip`与`description`，不会仅因敌人同名就跨对象复制状态或数值。
其他敌人需分别读图标和数字，也可用同图悬停窗口旁的图标帮助认名。
自动模式多一次短标题请求，总时限仍覆盖全部请求，显示费用包含两次调用；标题看不清时用通用模式并提示手选，
不凭文件名、对局日志或历史记录判断游戏。已明确游戏时手选适配可节省这次请求。

| 状态 | 含义 |
| --- | --- |
| `recognized` | 画面类型已识别，结构检查通过且未报告关键字段缺失；仍需对照图片核对 |
| `partial` | 结构有效，但有模糊或未识别信息 |
| `unrecognized` | 返回了有效结构，但不能确认画面类型 |
| `failed` | 图片、服务或返回格式错误，没有采用局面结果 |
| `timeout` | 等待到期，本次停止等待，不采用晚到的结果 |

`ok=true`表示结构校验通过，包括partial/unrecognized，不能理解为识别准确率100%。
CLI结构有效返回0，输入/模型/解析失败返回2。最长等待默认60秒（含网络退避重试），允许范围为大于0且不超过300秒。

## 原生采集验证

`scripts/check_window_capture_native.py`会创建一个独立测试窗口显示E10图片，再通过真实Win32接口采集；
默认不调用模型，加`--online`才进行模型调用。该测试验证客户区像素和最小化/关闭处理，测试窗口不是游戏进程。
当前1920×1124测试画面逐像素一致，真实模型完成识别。Windows渲染路径差异仍需在实际游戏中测试。
窗口采集的14个服务/底层测试及5个界面调度测试包含在当前114个离线用例中。
参考MAA的PC连接方案见`docs/窗口采集-MAA参考.md`。
