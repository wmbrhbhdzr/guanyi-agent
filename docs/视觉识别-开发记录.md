# 视觉识别开发记录

日期：2026-11-03。实验6后的项目增量，尚未归属下一次实验报告；按约定暂不提交仓库，待下一次报告一同提交。

## 本阶段目标与边界

让观弈从“手工录入局面”迈向“由截图获得结构化局面”。本阶段接通文件输入，保留未知值、保存识别证据，
先使一次识别可运行、可核对。沿用已有模型接口，不引入游戏数据读取、RAG或自动执行。
目前没有连接实时截屏，也没有把视觉结果接入规则基线或Agent，因此不能声称已经完成视觉决策闭环。

## 模块与过程

| 模块 | 职责 |
| --- | --- |
| `guanyi/vision/images.py` | 图片有效性、朝向、尺寸与元数据处理；形成可核对的输入快照 |

| `guanyi/vision/schema.py` | 类型与约束校验、缺失字段检查、生成只读摘要 |
| `guanyi/app/vision_service.py` | 组织模型调用、截止时间、错误反馈与记录保存；不依赖对局存储 |
| `guanyi/ui/vision_tab.py` | 图片预览、后台识别、主线程显示，处理成功、部分结果与失败 |
| `guanyi/cli.py` | `vision --image`入口，识别命令不初始化对局存储 |
| `scripts/vision_demo.py` | 可重复生成带已知读数的合成画面，选择性调用真实模型 |
| `tests/test_vision.py` | 24个离线视觉测试 |

复用已有 `LlmClient` 的多模态消息能力、网络错误处理和费用记录，复用实验6的有界等待。
没有把`.env`、图片文件名、路径、历史对局或预期答案放入模型上下文。
模型只看到固定提取说明与实际提交的PNG像素。

## 设计取舍与下一步

- 识别与决策分开：本阶段不把抽取结果冒充为合法动作，旧规则基线仍使用原手工输入。
- 拒绝猜默认值：不可见字段保留null，名称与费用不由卡牌知识补齐。
- 不定时自动请求：仅用户选择图片并点击后调用模型，控制无意义重复调用。
- 不固化宽泛游戏假设：支持多敌人和X费用，不把所有意图当作单段攻击；超出当前字段的机制暂不推算。
- 后续先收集少量真实截图，覆盖单敌人、多敌人、手牌重叠、地图和奖励页，离线人工标注后单独评估。
  标签只能用于评分，不能加入视觉模型输入。结果稳定后再接游戏窗口采集与建议链路。

## 2026-11-10 实际截图问题复核与增量修复

### 失败原因

检查当天10份实际截图识别记录，8份失败、2份部分成功。8份失败均为 `finish_reason=length`、
`completion_tokens=2500` 且 `reasoning_tokens=2500`，正文为空。首版将它们统一转成“检查密钥/网络”，误导定位。
`16940…`还记录了2次网络尝试，但旧版没有逐次错误历史，无法还原其首次尝试失败原因。

修正：视觉调用显式设置`thinking.type=disabled`，输出预算4096；该设置不会影响旧问答或Agent调用。
错误提示分类，记录finish_reason、输出/推理用量、预算与尝试次数，界面直接给出原因与处理建议。
设置依据：[DeepSeek思考模式官方文档](https://api-docs.deepseek.com/guides/thinking_mode/)。

### 游戏适配与参考图

新增通用/杀戮尖塔2可选适配，避免把一个游戏的显示约定固化到全项目。
数据库中增加4种敌人外形图与8种增减益图标，来源、哈希、分类与计数类型见`knowledge/visual/sts2/`。
通用模式不加载参考图。当前血量、意图、增减益数值仍只能取自本次截图；参考只提供身份外形。

杀戮尖塔2规则明确：单次攻击省略乘号，完整可见且无格挡标记的区域代表0；遮挡仍用null。
“笨拙”依据公开卡牌资料纠正为诅咒、不可打出、虚无，cost=null，并保留规则来源和原始识别费用。
视觉输出扩充玩家/敌人statuses（name、amount），兼容旧模型无statuses的返回。
数值不一概叫层数：难以杀灭9表示单次伤害上限；未显示数字时保留null，不根据单层型状态自动补1。

## 同日追加：悬停窗口与模式选择复核

用户最新记录`vision-5ac3dee6ebcd4fa4b28e660381f52bb6`确实仍显示“笨拙费用1”，
但其`game_profile=generic`，没有加载STS2规则或参考图。另有一条`vision-2ce056…`仍来自vision-v1旧进程。
为减少模式误选，界面/CLI默认改为自动模式：额外短请求仅根据图片可见标题判定已支持的游戏，
程序验证返回标题包含Slay the Spire 2/杀戮尖塔2才允许启用STS2适配。其余回退通用，手动选项保留。
不会根据文件名、历史对局或界面像卡牌游戏来选择适配。重启应用后新默认值生效。

第二个漏检原因是旧提示只要求“血条下方”而忽略悬停窗。
vision-v4增加tooltips原文提取与对象索引，优先读可见悬停文字；状态可标记source/description，
同名多敌人仅按关联对象引用详情，其他对象仍需独立看图标和数值。解析兼容原来的无tooltips结构。

真实复测采用同一张最新截图，记录`vision-51459e5440f34b0690ffd38bdec65d58`，总耗时4797.8 ms：

- 自动从窗口标题Slay the Spire 2选择STS2，笨拙cost=null并标注诅咒/不可打出/虚无。
- 玩家107/107、能量2/3；三敌18/24、26/26、25/25，格挡均0。
- 左侧攻击1×3，中间8×1，右侧蓝色向上箭头（增益），不编造具体增益效果。
- 三只敌人分别提取难以杀灭9；玩家无增减益。
- 两个悬停窗均关联enemy索引0：“攻势：这个敌人将要攻击造成1点伤害3次。”
  及“难以杀灭：外骨骼虫受到的所有伤害和生命减少效果不会超过9点。”

进一步补充标题选择/费用累计、未知标题回退、悬停只关联单个敌人、索引校验与鉴权失败停止测试，
当前合计 **91个离线测试通过**。这只证明本图复测与这些边界通过，不等于任意图标或任意悬停都能准确识别。

## 同日追加：游戏窗口采集
