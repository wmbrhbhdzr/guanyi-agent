## 五、未符合预期的分析与处理（如实记录）

| 现象 | 定位 | 处理 |
| --- | --- | --- |
| UI 冒烟里 Agent 校验未通过（`compute_stats_called=false`） | 测试夹具问题：冒烟用的是临时数据目录，里面没有 `run-0001` | 冒烟脚本改为先 `seed_sample_run`，并让假模型的结论数字与样例一致 → 校验通过 |
| 日志里出现 `task-***` 而不是完整任务号 | **真实 bug**：遮挡正则 `sk-[...]` 没有限定前缀，把 `task-20261027_085539` 里的 `sk-2...` 当成密钥片段遮挡了 | 已修正为正则加负向断言 `(?<![A-Za-z0-9])sk-...`，任务号完整显示，真实密钥仍被遮挡；单测 `test_13` 复测通过 |
| 工具失败后模型可能重复调用同一失败参数 | 控制流程 | 由“连续工具错误上限 = 2”兜住，达到即结束并给 `tool_errors` |
| 知识检索没有命中 | 结果分类规则 | 明确为 `ok=true, insufficient=true`，有效的“资料不足”不等于工具故障 |

## 六、结论

1. 五类场景全部有自动化用例覆盖，且**正常流程有一次真实模型运行**，满足讲义“正常流程必须实际调用模型和工具”。
2. 关键限制确实由程序执行：白名单/参数/路径/步数/时限/确认/校验都有对应用例，不依赖提示词。
3. 人工确认的三种结果（同意、拒绝、等待超时）都验证了“拒绝或超时则不执行”。
4. 已知局限：成功校验是规则级（数字与字段），不是语义级；超时只是停止等待，无法强制中断远端调用。
