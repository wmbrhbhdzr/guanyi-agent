# 实验7固定评测集

10个统一编号：E01—E08为合成/边界图，E09—E10为实际游玩截图。
真实图仅有两张、同一战斗的不同时间，不能当作独立场景充分覆盖。
`cases/*.json`包含模型外评分标签与输入SHA-256，`inputs/*.png`是两版共用输入。
合成图按绘图参数生成标签，真实图按可见内容设置检查点。评分脚本逐项比较输出与标签。

```powershell
# 已有固定输入不必重建；首次准备或有意重建时才运行
.\.venv\Scripts\python.exe scripts\build_exp7_evalset.py

# 真实收费模型评测；已存在结果会复用，避免重复计费
.\.venv\Scripts\python.exe scripts\run_exp7_eval.py --online

# 不联网，汇总现有评测结果
.\.venv\Scripts\python.exe scripts\run_exp7_eval.py
```

基线为按session中2026-11-03首版重建的`baseline-v1-reconstructed`：
原始vision-v1提示、2500 token、不显式设置thinking、不使用游戏规则/参考图、无statuses或tooltips。
基线按首版记录恢复提示词和参数；两版配置保存在`versions/`。
双方共用当前图片有效性检查与Schema公共检查；黑屏两版都拒绝，因此不把这项当作修订提升。
修订版使用当前`vision-v4`及自动标题识别，参数集中于`guanyi/vision/config.py`。
两方案同时期重跑同一批输入、同一固定字段规则；预期值不进入任何模型消息。

每份结果保存完整观察、原始模型正文、关键用量、耗时、费用估算和逐字段判断。
摘要区分字段通过率和全项通过样例数，任何一次失败都不隐藏；单次实测不能证明统计显著性。
若HTTP请求失败，未返回的实际用量不可得，费用为“已返回用量的估算”，不能视作账单精确总价。
图像数据的版权归游戏开发商；真实截图为用户提供的单机游戏测试材料，仅用于课程与原型评测。
本目录特意随代码保留少量固定评测输入与脱敏结果；普通对局记录仍在被Git忽略的`data/`中。

## 合成图如何生成

不是AI绘图。`scripts/vision_demo.py`用Pillow绘制基础画面，`scripts/build_exp7_evalset.py`修改其中单一条件：

- E01：基础图，HP68/80、能量3/3、格挡5、三张牌和敌人意图。
- E02：重画玩家栏为HP10/80、能量0/3、格挡0。
- E03：第一张牌改名为WHIRLWIND，费用改为X。
- E04：敌人意图改为2×3。
- E05：实色遮挡玩家栏。
- E06：只裁出玩家栏，保留原图比例。
- E07：绘制非战斗设置页面。
- E08：生成1000×650纯黑图片。

报告图1为编号概览，图1-1至图1-4每张只排两例，保留输入原图内容，避免缩略图文字过小。
这些排版图片不参与模型输入，`inputs/`和现有评测结果不变。
